## Image processing in native LabVIEW

Read PNG, display at actual image size, convert to a 1-bit pixmap using course picture VIs, unflatten to 2D Boolean array [row,column]. Verify polarity: TRUE means black; invert once if native palette indices produce the inverse. PNG size: each dimension 32..4096, provisional resource bound. Axis-aligned grid. First detect the bounding rectangle of black pixels (row/column OR reductions). Scan row top+10 and column left+10 (0-based), add FALSE at both ends, count rising/falling transitions; runs are complete grid strokes including those touching image edges. Number of runs minus 1 is number of cells. Require equal, even row/column counts, at least 2. Reject missing/merged strokes and invalid crop bounds. Image scan geometry assumption (strokes present 10 pixels inside the detected top/left outer border) is explicit, not universal arbitrary-image support.

Crop each cell INTERIOR from end-exclusive of stroke c to start of stroke c+1, and same for row. This excludes border thickness including the approximately 5px exterior margin. ComputeCellRect returns left,top,right,bottom with right/bottom exclusive, I32; array subset uses row=top, col=left, lengths bottom-top/right-left. Native rectangle clusters, if used, are created from the actual terminal; our project rectangle has ordered fields left,top,right,bottom. Do not silently substitute one cluster for another.

Threshold controls: DBL percent, empty 98.0, zero 90.0, one 90.0 (PROVISIONAL defaults for border-free crops). Empty supplied CellEmpty.bin retains substantial grid border: test its historical fixture using 88,90,90, not the interior-crop preset. Defaults are not official constants. No threshold selection/design is required from operators.

## OCR invocation

`OCR <Cell.bin-path> <empty-percent> <zero-percent> <one-percent>` (Windows executable OCR.exe). EXACTLY four user arguments, argc=5. P26 p23 says 5 parameters while including argv[0]; no fifth user argument. All thresholds required; finite ordinary base-10 decimal [0,100], dot decimal separator, no whitespace/exponent/hex/suffix/trailing junk; signed forms, .5 and 100. are accepted. Paths quoted by host command rules. Output always beside the input file, independent of process current directory (provisional output location). LabVIEW sets working directory to runtime too. POSIX shell quote helper escapes single quotes; Windows uses cmd /d /s /c with nested double quotes, rejects unsafe command metacharacters as documented in guide. stdout empty; stderr empty on success. Errors use `OCR E<number>: description` plus LF on stderr; no interactive prompts.

## Cell.bin binary

Exactly: width U32 little-endian (4 bytes); height U32 little-endian (4 bytes); width*height U8 pixels, each 0 white or 1 black. Payload order: top to bottom, left to right, offset=8+row*width+col. Header is NOT U8; P26 pp20-22 and supplied 5484-byte 74x74 fixtures resolve pp7/15 shorthand. Width precedes height. LabVIEW writes explicit [width,height] U32 then flattened U8 array, prepend array size FALSE on both writes. This avoids implicit 2D row/col dimension inversion in Exo.LabVIEW.1 p9. Rectangular tests are mandatory.

Dimension policy: 10..256 inclusive per dimension, provisional; a generous implementation bound; supplied cropped cells and 74x74 fixtures fit comfortably. P26 p19 gives 10..100 as an example of reasonable bounds, not a fixed final error table. Nonempty cell must fit 32x32 template; small all-white cells can be empty. Reject short headers, too few AND too many pixels, invalid pixel values. P26 p19 explicitly says no more/no less. Reject overflow before allocation; malloc and one bulk fread for pixels, free on every path. No VLAs.

## Recognition

Use supplied FontRasterized_0_1.h unmodified and cast each packed int32 row to uint32 before bit operations. Column 0 is bit31, column31 is bit0. Every translation (x=0..width-32, y=0..height-32 inclusive) counts equal black AND white pixels over 1024. Score=100*best_count/1024.

First, empty if whole-cell white percentage is STRICTLY GREATER than empty threshold (P26 p10; OCR exercise p3). Then retain digits whose score >= their own threshold (P26 p18). Default selection maximizes score-threshold; tie favors higher raw score, then digit 0. Margin selection is PROVISIONAL: p18 conflicts with raw-score choice on p10 and OCR exercise p3. `OCR_SELECT_BY_MARGIN` in c/ocr_policy.h isolates this choice. No-match is error 5, not a guessed digit or empty cell. Digit ties/equality are provisional and tested explicitly.

## CellValue.txt text

ASCII only, one line, LF terminated: `d:'0',93.7500%\n`, `d:'1',93.7500%\n`, or `d:' ',100.0000%\n`. Empty symbol is ONE ASCII space (provisional). No extra commentary or spaces. Four digits after decimal point. Empty percent is white percentage; digit percent is raw similarity, not margin. Compare unrounded values; round only on serialization. Parser accepts only 0,1,space, comma, 0..100 dot-decimal with exactly 4 fractional digits and one newline (CRLF accepted after transport conversion). It rejects malformed/trailing data. Convert blank to MATLAB `NaN`.

Exit 0 success; 2 argument/path; 3 dimensions/format including premature EOF; 4 actual stream/open/allocation failures; 5 no recognition; 6 output I/O. On a valid input path, old CellValue.txt is removed before processing; an output failure never leaves a new partial result. Argument errors before path discovery may leave old output; LabVIEW never reads output unless error cluster clear AND exit=0 AND stderr empty. It also removes old result before each call. Missing/invalid result is a pipeline error.

## MATLAB and generated script

Matrix B is n-by-n real double, symbols 0,1,NaN, n even >=2. Preserve original clues. Validation rejects invalid shapes, values and initial contradictions. Invalid/unsatisfiable grid returns valid=false without changing caller original. DirectValues propagates single possible values to a fixed point before each guess; recursion branches 0 then1 at first remaining empty in MATLAB column-major order (consistent with the P26 p30 example and find). Candidate tests enforce no consecutive triple, counts <=n/2, and uniqueness of completed rows/columns only. Empty/nonunique puzzles return first valid solution; no uniqueness claim. Avoid for/while in assessed MATLAB functions: vectorized checks plus recursive propagation and recursion for search. This satisfies inherited loop preference without removing required deduction or backtracking.

Generated solve.m defines `B`, `sourceFile` (absolute user-selected path escaped as MATLAB literal), `solveWithMatlab` and `showPDF` logicals then calls `RunBinairo(B,sourceFile,solveWithMatlab,showPDF)`. Booleans default TRUE/TRUE provisionally. RunBinairo calls SolveBinairo if solving enabled; DisplayBinairo renders PDF whenever MATLAB launched. When solve=false, render original clues only, without false error for an incomplete unattempted puzzle. PDF name is source basename + `.pdf`, located in runtime (not next to possibly read-only input image). Original digits black bold; inferred blue bold; full grid; source filename upper left; timestamp upper right; infeasible centered `== Error ==`. `showPDF` controls opening finished PDF, never whether it is written. P26 pp24/32/35 do not fully define disabled options; these semantics are provisional.

Script outcome files runtime: MatlabStatus.txt exact `OK\n`, `UNSOLVABLE\n`, or `ERROR\n`; MatlabError.txt full extended error report on exception; MatlabRun.log diary. Delete stale status/error/PDF before launch. Both OK and UNSOLVABLE indicate script completed; latter is a displayed puzzle error with error PDF. Launcher/native error or missing fresh status is failure. MATLAB internal errors are caught, status saved and then rethrown so native launcher can also detect failure. Native tests remain pending; Python checks are not MATLAB execution.

Temporary output: CellValue.txt.tmp is closed before rename to CellValue.txt. Both names are reserved input basenames (case-insensitive). Single runtime writer only.

Native image handling: Read PNG File Transparency Thresh U8=128, original mask preserved through Draw Flattened Pixmap, white Picture to Pixmap background, depth1. This is binary alpha masking, not fractional-alpha blending. Validate palette polarity natively; explicit calibration is required only for an empty/default returned palette. The development Pillow surrogate uses a different conversion and therefore cannot establish native bitmap equivalence. Input raster32..4096 pixels per dimension is a provisional resource limit; cell10..256 remains independent.

LabVIEW threshold entry policy:0..100 with at most four decimal places; command format uses4 decimals. A format/parse roundtrip must exactly match the stored DBL or error7004; no silent rounding of a higher-precision user value. C standalone CLI grammar remains broader. Defaults98/90/90 are unchanged.
